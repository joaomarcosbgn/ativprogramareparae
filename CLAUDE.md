

# REPARAÊ — GUIA PRINCIPAL DO PROJETO

## 1. SOBRE O PROJETO

O Reparaê é uma plataforma ampla de conexão entre pessoas que precisam de serviços e profissionais que oferecem esses serviços.

A ideia central é funcionar como um "delivery de serviços".

O Reparaê NÃO é limitado a serviços domésticos, residenciais ou de manutenção.

A proposta é reunir uma ampla gama de serviços em uma única plataforma, permitindo que o usuário encontre rapidamente o profissional necessário para resolver diferentes tipos de necessidades.

Exemplos de serviços:

* Encanador
* Eletricista
* Mecânico
* Faxineiro(a)
* Fotógrafo
* Designer
* Professor particular
* Técnico de informática
* Profissional de beleza
* Fotógrafo para eventos
* Profissional para festas
* Transporte e mudanças
* Cuidados com pets
* Serviços de tecnologia
* Serviços automotivos
* Serviços para empresas
* Serviços profissionais
* Entre muitos outros

Esses exemplos são apenas ilustrativos. A plataforma deve possuir capacidade para receber diferentes categorias e tipos de serviços.

O principal objetivo do sistema é:

"Precisou? Reparaê."

A experiência deve transmitir a ideia de:

PROBLEMA / NECESSIDADE → PROCURA → PROFISSIONAL → SOLUÇÃO

O usuário deve conseguir encontrar o serviço que precisa com o menor número possível de etapas.

O GetNinjas deve ser utilizado como referência para:

* Estrutura geral do serviço
* Organização das categorias
* Cadastro de clientes
* Cadastro de profissionais
* Descoberta de serviços
* Fluxo de contratação
* Apresentação de profissionais
* Avaliações
* Estrutura de páginas
* Experiência tanto no computador quanto no celular

Outra referência importante é o iFood.

O iFood deve ser utilizado principalmente como referência de:

* Organização da página inicial
* Descoberta rápida de categorias
* Busca
* Serviços/categorias populares
* Organização visual
* Navegação simples
* Hierarquia das informações
* Experiência mobile
* Sensação de "delivery"

O Reparaê deve combinar esses conceitos:

GETNINJAS = marketplace de serviços

IFOOD = experiência de descoberta e delivery

REPARAÊ = DELIVERY DE SERVIÇOS

IMPORTANTE:

Não copiar literalmente o design, textos, imagens, logotipos ou elementos proprietários dessas empresas.

Utilizar apenas conceitos de experiência, estrutura e organização como inspiração.

O Reparaê precisa possuir identidade visual própria.

---

# 3. OBJETIVO DA EXPERIÊNCIA

O site deve ser extremamente direto.

Quando uma pessoa entrar no Reparaê, ela deve entender rapidamente:

1. O que é o Reparaê
2. Como ele pode ajudá-la
3. Como encontrar um serviço
4. Como contratar um profissional

Evitar excesso de informações antes da ação principal.

A prioridade da interface deve ser:

1. Encontrar um serviço
2. Encontrar um profissional
3. Entrar em contato/solicitar serviço
4. Criar uma conta quando necessário

A interface deve ser intuitiva mesmo para alguém que nunca utilizou o sistema.

Sempre que existir uma maneira de realizar uma ação com menos cliques, considerar essa opção.

# 6. EXPERIÊNCIA DESKTOP E MOBILE

O Reparaê precisa funcionar muito bem tanto em:

* computador
* tablet
* celular

A versão mobile é extremamente importante.

Não criar apenas uma versão desktop e simplesmente "diminuir" para celular.

A experiência mobile deve ser pensada separadamente quando necessário.

A interface deve utilizar:

* menus adaptados
* botões fáceis de tocar
* campos adequados para celular
* navegação simples
* boa hierarquia visual
* elementos responsivos

No desktop, utilizar melhor o espaço horizontal.

No mobile, priorizar:

* busca
* categorias
* serviços populares
* profissionais
* ações principais

# 7. ESTRUTURA GERAL DO SITE

O sistema deve possuir uma estrutura semelhante à experiência de grandes marketplaces de serviços, utilizando o GetNinjas como referência de abrangência.

A plataforma deve contemplar uma grande variedade de categorias de serviços.

Não limitar a plataforma a:

* serviços domésticos
* manutenção residencial
* construção
* limpeza
* reparos

Essas categorias podem existir, mas representam apenas uma parte do marketplace.

O sistema deve ser preparado para categorias como, por exemplo:

* Casa e manutenção
* Automotivo
* Tecnologia
* Educação
* Fotografia e vídeo
* Design e criatividade
* Beleza e estética
* Pets
* Transporte e mudanças
* Eventos
* Limpeza
* Assistência técnica
* Serviços profissionais
* Esporte e bem-estar
* Cuidados e assistência
* Serviços para empresas
* Entre outras

A lista acima não precisa ser seguida literalmente.

O agente pode sugerir uma organização melhor das categorias, desde que mantenha a proposta de uma plataforma ampla de serviços.

Se durante o desenvolvimento for identificada alguma página ou fluxo importante que não tenha sido especificado neste documento, o agente pode sugerir sua inclusão.

Não criar páginas apenas para aumentar a quantidade.

Cada página deve possuir uma função clara.

---

# 8. PRIMEIRA PÁGINA / LANDING PAGE

A primeira página deve apresentar o Reparaê para uma pessoa que ainda não possui conta.

A página deve possuir uma primeira área de destaque muito clara.

Essa área deve comunicar:

* Reparaê
* "Precisou? Reparaê."
* ideia de delivery de serviços
* chamada para ação
* login

Deve existir uma área de login contendo, no mínimo:

* E-mail
* Senha
* Botão de entrar
* Opção para cadastrar

Exemplo conceitual:

"Faça seu login"

"E-mail"

"Senha"

"Entrar"

"Não possui uma conta? Cadastre-se"

O layout deve ser moderno e visualmente forte.

Também deve existir uma área explicando:

"Como funciona?"

Essa seção deve explicar de maneira simples como o Reparaê conecta pessoas que precisam de diferentes tipos de serviços aos profissionais capazes de realizá-los.

Exemplo conceitual:

1. Encontre o serviço
2. Escolha o profissional
3. Entre em contato
4. Resolva sua necessidade

O agente pode melhorar esse fluxo conforme a experiência do sistema.

---

# 9. AVALIAÇÕES NA LANDING PAGE

A página inicial pública deve possuir uma seção de avaliações.

As avaliações devem representar:

* clientes
* profissionais

A ideia é demonstrar confiança e mostrar que o sistema atende os dois lados do marketplace.

As avaliações podem abordar diferentes tipos de serviços, reforçando que o Reparaê não é limitado a uma categoria específica.

A apresentação deve ser moderna e visualmente agradável.

Evitar criar avaliações falsas apresentadas como reais.

Se forem utilizados dados fictícios para protótipo acadêmico, deixar a estrutura preparada para posteriormente receber dados reais da API.

---

# 10. SEÇÕES INSTITUCIONAIS

A página pública deve possuir seções comuns a plataformas profissionais, como:

* Sobre o Reparaê
* Como funciona
* Para clientes
* Para profissionais
* Seja um profissional
* Avaliações
* Perguntas frequentes
* Rodapé
* Termos
* Privacidade

Essas seções devem ser organizadas de forma que não atrapalhem o objetivo principal da plataforma.

A pessoa deve conseguir encontrar rapidamente o serviço que precisa, independentemente do tipo de serviço.

---

# 11. CADASTRO

Ao clicar em "Cadastre-se", o usuário deve primeiro escolher o tipo de conta.

A primeira tela de cadastro deve apresentar duas opções claramente diferentes:

CLIENTE

PROFISSIONAL

A escolha deve determinar o fluxo seguinte.

---

# 12. CADASTRO DE CLIENTE

O cadastro do cliente deve ser simples e solicitar somente as informações necessárias.

Possíveis informações:

* Nome
* E-mail
* Senha
* Telefone
* Informações básicas necessárias para utilização da plataforma

Não criar campos desnecessários.

Após preencher corretamente, o usuário deve conseguir finalizar o cadastro de maneira simples.

---

# 13. CADASTRO DE PROFISSIONAL

O cadastro do profissional deve possuir mais etapas que o cadastro de cliente.

A experiência deve ser dividida em etapas para não apresentar um formulário enorme de uma vez.

ETAPA 1 — DADOS PESSOAIS

Exemplos:

* Nome
* Telefone
* E-mail
* Senha
* Localização/região de atendimento
* Outras informações realmente necessárias

Depois:

"Continuar"

---

# 14. CADASTRO DE SERVIÇOS DO PROFISSIONAL

Na segunda etapa, o profissional deve informar quais serviços oferece.

O sistema deve utilizar uma estrutura hierárquica.

Exemplo conceitual:

CATEGORIA

→ Casa e manutenção

→ Automotivo

→ Tecnologia

→ Educação

→ Beleza

→ Eventos

→ Fotografia

→ Transporte

→ Pets

→ Serviços profissionais

→ Entre outras categorias

Quando o profissional escolher uma categoria, devem aparecer os serviços específicos daquela categoria.

Exemplos:

AUTOMOTIVO

→ Mecânica

→ Elétrica automotiva

→ Funilaria

→ Pintura automotiva

TECNOLOGIA

→ Manutenção de computador

→ Instalação de software

→ Suporte técnico

→ Desenvolvimento

EVENTOS

→ Fotografia

→ Filmagem

→ DJ

→ Decoração

CASA E MANUTENÇÃO

→ Encanamento

→ Elétrica

→ Limpeza

→ Pintura

→ Montagem

O profissional pode selecionar MAIS DE UM serviço.

O sistema deve permitir selecionar múltiplas categorias e serviços.

A organização deve ser visualmente simples.

Evitar mostrar dezenas de opções de uma vez.

Utilizar menus, cards, listas, pesquisa ou agrupamentos quando isso melhorar a experiência.

O agente deve pesquisar e sugerir uma estrutura de categorias coerente com um marketplace amplo de serviços, utilizando como referência conceitual o GetNinjas e boas práticas de UX.

As categorias não devem ficar limitadas aos exemplos deste documento.

---

# 15. FINALIZAÇÃO DO CADASTRO PROFISSIONAL

Após selecionar os serviços, o profissional deve conseguir finalizar o cadastro.

A experiência deve mostrar claramente o progresso.

Exemplo:

Dados pessoais
↓
Serviços
↓
Área de atendimento
↓
Conclusão

O agente pode sugerir outras etapas caso sejam realmente necessárias.

Evitar formulários excessivamente longos.

---

# 16. PÁGINA PRINCIPAL APÓS LOGIN

Depois que o cliente entrar na plataforma, a página principal deve funcionar como o "shopping" ou "delivery" de serviços.

Essa deve ser uma das páginas mais importantes do sistema.

Ela deve possuir uma barra de pesquisa em posição de destaque.

Exemplo:

"Qual serviço você precisa?"

A pesquisa deve permitir procurar diretamente pelo serviço.

Exemplos:

"Encanador"

"Fotógrafo"

"Mecânico"

"Professor de inglês"

"Designer"

"Eletricista"

"Fotógrafo para casamento"

"Conserto de computador"

"Personal trainer"

"Cuidador de pets"

etc.

A busca deve representar a amplitude da plataforma.

---

# 17. CATEGORIAS DE SERVIÇOS

A página inicial deve apresentar categorias de serviços.

As categorias devem abranger diferentes áreas e não apenas serviços domésticos.

Exemplos:

* Casa e manutenção
* Automotivo
* Tecnologia
* Educação
* Fotografia e vídeo
* Design e criatividade
* Beleza e estética
* Pets
* Transporte e mudanças
* Eventos
* Limpeza
* Assistência técnica
* Serviços profissionais
* Esporte e bem-estar
* Cuidados e assistência
* Serviços para empresas
* Entre outras

As categorias devem possuir apresentação visual através de cards, ícones ou imagens.

No desktop, quando o usuário passar o mouse sobre uma categoria, deve ser possível apresentar os serviços específicos daquela categoria.

No mobile, utilizar uma interação adequada para toque, já que hover não existe da mesma maneira.

O comportamento deve ser intuitivo.

---

# 18. SERVIÇOS POPULARES

A página inicial deve apresentar uma área:

"Serviços populares"

ou uma variação melhor de texto.

Mostrar os serviços mais procurados.

Os serviços populares devem representar diferentes áreas da plataforma, não apenas serviços residenciais.

O objetivo é permitir que o usuário encontre rapidamente algo que provavelmente está procurando.

---

# 19. SERVIÇOS MAIS PEDIDOS

Também deve existir uma área para:

"Mais pedidos"

ou conceito semelhante.

Essa área deve ser preparada para futuramente receber dados reais da plataforma.

Não criar números ou estatísticas falsas como se fossem dados reais.

---

# 20. BUSCA

A busca deve ser uma das funcionalidades mais importantes do Reparaê.

O usuário deve poder digitar diretamente o que precisa.

Exemplos:

"Preciso de um encanador"

"Quero um fotógrafo"

"Preciso de um mecânico"

"Professor particular"

"Designer"

"Eletricista"

"Conserto de televisão"

"Personal trainer"

A experiência deve ser simples e rápida.

Quando possível, utilizar sugestões enquanto o usuário digita.

A busca deve conseguir lidar com diferentes tipos de necessidade e não assumir que o usuário está procurando necessariamente um serviço doméstico.

---

# 21. RESULTADOS DA BUSCA

Os resultados devem apresentar profissionais/serviços de maneira clara.

Um card de profissional pode apresentar:

* Nome
* Foto
* Categoria/serviço
* Localização
* Avaliação
* Quantidade de avaliações
* Breve descrição
* Botão para visualizar
* Botão para entrar em contato/solicitar

Não sobrecarregar o card com informações.

A prioridade é ajudar o cliente a escolher rapidamente.

---

# 22. PERFIL DO PROFISSIONAL

O perfil profissional deve apresentar informações suficientes para que o cliente tenha confiança antes de entrar em contato.

Possíveis informações:

* Foto
* Nome
* Serviços
* Região atendida
* Descrição
* Avaliações
* Nota
* Trabalhos/portfólio quando disponível
* Informações de contato conforme as regras do sistema
* Botão principal para solicitar/entrar em contato

A página deve transmitir confiança.

O perfil deve ser adaptável a diferentes profissões.

Um fotógrafo, por exemplo, pode precisar de portfólio visual.

Um mecânico pode apresentar serviços automotivos.

Um professor pode apresentar áreas de ensino.

Um profissional de tecnologia pode apresentar especialidades.

O layout deve suportar diferentes tipos de profissionais sem criar uma página diferente para cada profissão.

---

# 23. EXPERIÊNCIA DO CLIENTE

O cliente deve conseguir:

* pesquisar serviços
* navegar por categorias
* encontrar profissionais
* visualizar perfil
* visualizar avaliações
* solicitar/entrar em contato
* acompanhar solicitações
* visualizar histórico
* editar perfil

Se alguma funcionalidade adicional for necessária para completar a experiência, pode ser sugerida.

---

# 24. EXPERIÊNCIA DO PROFISSIONAL

O profissional deve possuir uma área própria.

Ele deve conseguir visualizar e administrar:

* perfil
* serviços oferecidos
* área de atendimento
* solicitações
* clientes
* avaliações
* informações da conta

A interface deve ser diferente o suficiente para deixar claro que é uma área profissional, mas manter a mesma identidade visual do Reparaê.

---

# 25. NAVEGAÇÃO

A navegação deve ser extremamente simples.

No desktop, utilizar uma barra de navegação clara.

No mobile, utilizar uma estrutura adequada para celular.

Considerar uma navegação inferior quando isso melhorar a experiência.

Possíveis áreas:

* Início
* Buscar
* Solicitações
* Perfil

Para profissionais, adaptar para:

* Início
* Solicitações
* Serviços
* Perfil

Não adicionar itens apenas por adicionar.

---

# 26. DESIGN

O design deve transmitir:

"moderno + simples + confiável + rápido"

Evitar:

* excesso de sombras
* excesso de animações
* excesso de cores
* telas visualmente poluídas
* textos enormes
* formulários desnecessariamente complexos
* menus confusos

Utilizar bastante espaço em branco.

Os botões principais devem ser muito claros.

A ação principal de cada página deve ser evidente.

---

# 27. MERCHANDISING / POSICIONAMENTO

Queremos comunicar em algum ponto estratégico do site a ideia:

"Delivery de serviços"

ou

"O delivery de serviços"

ou alguma frase equivalente.

Essa comunicação pode aparecer em:

* banner
* hero da página
* seção institucional
* cards
* rodapé
* campanhas visuais

O agente pode escolher a melhor posição.

Não repetir excessivamente.

---

* brasileiro

* tecnológico

* amigável

Sempre pensar:

Sempre priorizar:

CLAREZA

VELOCIDADE

SIMPLICIDADE

CONFIANÇA

A experiência deve funcionar para diferentes necessidades e diferentes tipos de usuários.

---

# 31. REGRA FUNDAMENTAL

O Reparaê não deve parecer simplesmente um clone do GetNinjas.

O objetivo é:

APRENDER COM O GETNINJAS

*

APRENDER COM A EXPERIÊNCIA DO IFOOD

*

CRIAR UMA EXPERIÊNCIA PRÓPRIA

=

REPARAÊ

A experiência deve transmitir a sensação de que contratar um serviço é tão simples quanto pedir algo por delivery.

Porém, diferente de uma plataforma especializada em apenas um tipo de necessidade, o Reparaê deve ser amplo e permitir que o usuário encontre diferentes tipos de serviços.

Frase central da marca:

"Precisou? Reparaê."

Conceito:

"Delivery de serviços."

---

# 32. PRINCÍPIO FINAL

Antes de implementar qualquer página, sempre pensar:

"Como podemos fazer o usuário resolver a necessidade dele com menos passos?"

Essa pergunta deve orientar todas as decisões de interface e experiência do Reparaê.

Independentemente de qual seja o serviço procurado, a experiência deve continuar simples:

PRECISOU DE ALGO?

↓
PESQUISOU

↓
ENCONTROU

↓
ESCOLHEU

↓
ENTROU EM CONTATO

↓
RESOLVEU

Esse é o conceito central da experiência do Reparaê.
